What it needs

Four inputs, two owners

InputWho provides itExample
Where the bot livesTech teamProject “acme-cx”, region “global”, app ID from Google’s console
Test callsBusiness owner“Elderly caller gives the wrong order number, then corrects it”
House rulesBusiness owner“Verify identity before sharing order details”
Run settingsWhoever runs itText or spoken audio, how many repeats, how many coaching rounds

Each test call is a short description: who is calling, what they want, what they know, and what success looks like. No scripts to write.

WORKS FOR ANY USE CASE (45 sec). Writing test calls used to be the bottleneck. Now we hand it a PRD, a policy document, or a photo of the whiteboard call flow, and it drafts the test calls. From our sample PRD it drafted 8 test calls in about 25 seconds. More useful still, it listed 5 rules the PRD never actually defines, such as what makes an order eligible for a return. That surfaces requirement gaps before go-live, not after. We also tested it on a call-flow diagram, as an image and as a PDF, and it turned every branch into a test call. A person still reviews the draft before saving. Scoring is configurable per use case, so a compliance-heavy flow can weight rules higher than speed.
